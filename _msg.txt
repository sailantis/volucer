ci: the release job referenced a job from another workflow

`needs: [build, installers]` named an `installers` job that exists in ci.yml, not
in release.yml, so the release workflow failed to parse on the push that added
it. The installer check is already gated by ci.yml on every push, so the tag
only needs its own job for the half ci.yml cannot see: the *published* install.sh
against the *published* archives.

That job now fetches install.sh from the release rather than copying it out of
the checkout, because the checkout's copy is the one ci.yml already proves and
the published one is what a stranger runs. It also reads the archives out of the
tarball download-artifact uploads, since those are not extracted.

Verified by extracting the step's `run:` block and executing it against a real
archive from stage-archive.sh over HTTP - the same path the job takes. The
earlier version of this job compared against a directory that was never created
and copied an install.sh that was never in the workspace root.
